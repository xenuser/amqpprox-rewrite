# Build an RPM on RHEL 9

This tooling builds native RPM and SRPM artifacts on your RHEL 9 builder. No
container engine is required. RHEL 9 package builds have not been executed by
the author of this change; run the steps below on your approved builder.

## Dependencies

Use approved RHEL/CodeReady Builder/EPEL or internal mirrored repositories as
appropriate for your organization. Repository enablement requires your normal
subscription and change process. No script enables repositories automatically.

```sh
sudo dnf install git gcc-c++ make rpm-build rpmdevtools boost-devel openssl-devel \
  protobuf-devel protobuf-compiler gtest-devel gmock-devel systemd-rpm-macros python3
```

CMake **3.27 or newer** and matching `ctest` must also be installed. The stock
CMake in some RHEL 9 releases is older. Supply an approved newer CMake via PATH
or `CMAKE=/opt/cmake/bin/cmake`. The wrapper checks its actual version. It does
not download tools. If your organization allows Python tooling, a separate
virtual environment with an approved pinned CMake wheel is another option;
include its matching `ctest` in the same directory. Offline builders need all
RPM dependencies and the approved CMake toolchain staged in advance.

## Build

Commit the source first. The wrapper refuses dirty/untracked source files and
packages `git archive HEAD`, including the commit ID in the RPM release.

```sh
VERSION=0.1.0 CMAKE=/opt/cmake/bin/cmake make rpm-rhel9
```

The script invokes `rpmbuild -ba`, compiles the binaries, runs the C++ regression
suite in `%check`, and produces:

- `build/rpmbuild/RPMS/<architecture>/*.rpm`
- `build/rpmbuild/SRPMS/*.src.rpm`

An SRPM rebuild also needs CMake >=3.27; pass `--define 'cmake_binary /path/to/cmake'`
and `--define 'ctest_binary /path/to/ctest'` when these are outside `/usr/bin`.
Dynamic runtime library dependencies are generated by RPM. Build on RHEL 9 for
RHEL 9; the Ubuntu/WSL binaries are not RHEL deployment artifacts. Sign packages
with your organization's existing RPM signing process.

## Install and configure

```sh
sudo dnf install ./build/rpmbuild/RPMS/$(uname -m)/amqpprox-rewrite-*.rpm
sudoedit /etc/sysconfig/amqpprox-rewrite
sudoedit /etc/amqpprox/control.conf
sudo systemctl enable --now amqpprox-rewrite
sudo systemctl status amqpprox-rewrite
sudo journalctl -u amqpprox-rewrite
```

The package creates an unprivileged `amqpprox` account. It does not enable or
start the service on installation. The supplied control file is commented out:
startup fails until you configure backends, map the **destination** vhost, and
add the listener last. Command errors abort startup. Keep the runtime control
socket local and restricted; it is an administrative interface.

TLS certificate/key files must be readable by `amqpprox` under `/etc/amqpprox/`;
keys should be root-owned, group `amqpprox`, mode 0640. See
[the migration guide](../../docs/legacy-rewrite.md) for AMQPS configuration.
Listener ports must be above 1023 for this unprivileged service. Configure your
firewall and applicable SELinux policy for the listener, backend connections,
configuration and logs. Do not disable SELinux. This package does not ship a
custom SELinux policy; inspect AVC denials and follow your site policy.

Logs are in `/var/log/amqpprox` and the journal. Restart after configuration
changes. Run the [existing-server tests](../../tests/rabbitmq43/README.md)
before production cutover. The service is a single instance; deploy separately
configured instances/hosts for distinct rewrite mappings and availability.
